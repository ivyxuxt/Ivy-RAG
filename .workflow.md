# Workflow & Git Conventions

## Commit prefix format
```
backend: <what>   — e.g. "backend: add BM25 inverted index"
frontend: <what>  — e.g. "frontend: add citation card component"
local: <what>     — e.g. "local: update .rules.md with chunking assumptions"
scaffold: <what>  — e.g. "scaffold: initial project structure"
```

## Commit rules
- Every commit = one passing sanity test recorded alongside it
- Never mix frontend + backend changes in the same commit
- After each step, add any non-obvious assumption to `.rules.md`
- One logical change per commit — no "fix + refactor + add feature" combos

## Branch naming
```
main              — stable, always runnable
feature/<area>    — e.g. feature/ingestion, feature/hybrid-search, feature/frontend-chat
```

## Sanity test after each phase
| Phase | Sanity test |
|---|---|
| 0 | `GET /health` returns `{"ok": true}` |
| 1 | Upload 5-page PDF → chunks in chunks.jsonl with page metadata |
| 2 | Query phrase → top dense result is the correct chunk |
| 3 | Exact rare term → BM25 top-1 is the correct chunk |
| 4 | Hybrid > either individual method on paraphrase queries |
| 5 | "hello" → chitchat, "according to" → knowledge_lookup |
| 6 | Grounded answer with [S1] citations returned |
| 7 | Hallucination sentence flagged with status code |
| 8 | Upload + ask + see citations in UI |
| 9 | `docker-compose up` → /health reachable |
| 10 | Recall@5 ≥ 0.75 on eval set |

## Push protocol
- Push only after explicit user confirmation
- Command to push: `git push origin main`
